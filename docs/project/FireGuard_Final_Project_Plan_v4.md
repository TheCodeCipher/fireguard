## 0. Executive summary

**FireGuard** is a multimodal wildfire forecasting research prototype and historical decision-support application. It uses **WildfireSpreadTS (WSTS)** to predict the next day's Suomi-NPP VIIRS active-fire detection map for already-burning large wildfire events. The benchmark uses a 375 m grid and daily 24-hour samples. The primary output is a per-cell probability map of next-day active-fire detections; newly detected cells are a secondary analysis.

The v1 application has two distinct capabilities:

1. **Live Monitor — observations only:** show current/global active-fire observations from NASA FIRMS, with satellite/platform, processing source, confidence, FRP where supplied, acquisition time and data age. It does not display FireGuard live forecasts.
2. **Forecast & Replay Lab — historical research replay:** select a WSTS event and origin, retrieve a **precomputed out-of-fold (OOF) forecast artifact** generated by a model that did not train on that event, inspect probability/uncertainty/explanation layers, and reveal the next-day target only after the forecast is shown.

The default research model is the **strict no-GFS variant**: M1–M4 use only channels that pass the Level-A no-look-ahead audit, with GFS forecast channels excluded by default. GFS/FiLM is a separate **benchmark-assumption ablation** and is never described as operationally available unless it independently passes the Level-B availability audit. HLS and GNN are optional, evidence-gated experiments.

The main contribution is not the invention of U-Net or ConvLSTM. Prior WSTS work already compares spatial and temporal models. FireGuard's defensible contribution is a reproducible audit of input-time assumptions, soft-score baselines, grouped event/year/geographic evaluation, observability-aware diagnostics, fold-specific calibration, precomputed OOF replay, and transparent ablation/negative-result reporting.

**v1 forecasting is replay-only.** A global FIRMS observation map is feasible, but live model forecasting would require rebuilding and time-validating the full WSTS input stack in near-real time. This is out of scope for a six-person, ten-week project. Live model inference, 6/12-hour products, learned smoke movement, and non-U.S. forecast transfer are later work.

### One-sentence project pitch

> FireGuard is a leakage-audited multimodal wildfire forecasting research prototype that predicts next-day active-fire detections on the WSTS 375 m grid, evaluates calibrated probabilities on held-out fire events, and demonstrates results through a historical forecast-replay application alongside a separate global FIRMS observation map.

## 1. Final scope: what v1 will and will not do

### 1.1 Must-have v1 capabilities

1. Load and document WSTS, its data dictionary, original splits/baselines and data-use conditions.
2. Build a reproducible WSTS data loader and a frozen, event-level evaluation protocol.
3. Run non-learning baselines and a classical ML baseline where feasible.
4. Train a 2D U-Net baseline and a U-Net + ConvLSTM temporal model.
5. Use the **strict no-GFS model as the default** for M1–M4. Treat GFS/FiLM only as a separately labelled benchmark-assumption ablation after its Level-A no-look-ahead audit; make no operational-availability claim unless Level B is verified.
6. Produce calibrated next-day active-fire probability maps and an indicative uncertainty layer.
7. Store out-of-fold predictions for held-out events so the Replay Lab never presents in-sample predictions as valid forecasts.
8. Build the historical Forecast & Replay Lab with prediction-first / reveal-actual-after interaction.
9. Build the global FIRMS Live Monitor as an observation-only page.
10. Provide a Methodology / Data Sources / Limitations page, provenance metadata and a reproducible research report.

### 1.2 Should-have features, only after the must-have path works

- Two explainability methods with faithfulness checks (feature-group ablation/permutation plus Integrated Gradients or Grad-CAM).
- A small deep ensemble or MC-dropout/snapshot ensemble. Ensemble spread must be described as **indicative uncertainty**, not automatically as calibrated confidence. Explanation stability across ensemble members/seeds and attribution methods is a secondary analysis.
- Basic fire/smoke report form and a private human-review queue.
- Event-level label-noise audit against MTBS/perimeters or burned-area evidence for a matched subset.
- HLS historical-coverage feasibility audit and HLS training input, **only if the explicit go/no-go rule in Section 3.2 passes**.

### 1.3 Could-have research experiments

- Coarsened GNN (GCN or GAT) compared with a matched-parameter CNN.
- LANDFIRE pre-event fuel/canopy enrichment if a temporally appropriate version is available.
- More detailed regional/economic/ecological stratification if sample counts allow.

### 1.4 Explicitly later / out of scope for v1

- Live FireGuard-generated forecasts from current FIRMS observations.
- A globally validated forecasting model. FIRMS observations can be global; WSTS-trained forecasts are not globally validated.
- 6-hour and 12-hour forecast products. WSTS is daily; a higher-frequency experiment requires suitable geostationary observations and matched labels.
- Learned smoke-plume movement or smoke dispersion. An external smoke layer is also deferred in v1.
- Public emergency alerts, evacuation routes, safety guarantees or operational incident-command recommendations.
- Automatic use of crowdsourced reports as training labels.
- Native iOS/Android applications. v1 is a responsive web application.
- Kubernetes, MinIO, TiTiler, Redis, Celery and a production tile-server stack unless a demonstrated technical need appears.

### 1.5 Geographic wording

- **Forecast benchmark domain:** the retained WSTS large-fire events are located in the **western United States**. The paper describes 607 events from the contiguous U.S. search, but notes that the retained events are all in the western part because many central/eastern candidates were discarded.
- **Live observation domain:** NASA FIRMS provides global active-fire observation products.
- **Forecast display rule:** only display historical predictions for WSTS events/forecast origins covered by the relevant held-out fold. Outside that experimental set, show “forecast not available / outside evaluated benchmark coverage.”
- Do not label FireGuard “global wildfire forecasting.” Correct wording: “global active-fire observation layer plus a western-U.S.-benchmark-trained historical forecasting prototype.”

## 2. Exact prediction task, target and time definition

### 2.1 Benchmark-aligned primary task

The primary task matches the WSTS benchmark:

> Given preceding daily WSTS observations, predict the **next-day binarized Suomi-NPP VIIRS active-fire map**.

For each grid cell:

`P(active-fire detection in target day D+1 | preceding WSTS input sequence)`

This is a forecast of satellite-detected active-fire activity, not a verified physical fire perimeter or a prediction of new ignitions. Clouds, smoke, overpass geometry/timing and detection limitations can cause missed observations.

### 2.2 Secondary target: newly detected cells

A secondary analysis may compute:

`new_cell = active_fire(D+1) AND NOT active_fire(D)`

This measures newly detected cells, not necessarily newly ignited fire. Keep the benchmark-aligned next-day active-fire map as the primary training target so results remain comparable with WSTS literature.

### 2.3 Forecast window and two levels of time safety

Use the exact daily window and sample semantics implemented by the pinned WSTS loader. Do not invent a different origin convention. Define `target_start` as the start of the next-day label window under the WSTS convention.

Time safety must be recorded at two separate levels:

- **Level A — no look-ahead:** input content does not contain observations or derived information from at/after the start of the target window. Level A supports a historical no-look-ahead research replay; it does **not** prove that a user could have downloaded the input at the forecast origin.
- **Level B — operationally available:** source publication/processing/access time is verified to be at or before the chosen forecast origin (`available_at <= t0`). Only Level B can support an operational availability claim.

For every channel, record both `no_lookahead` and `operationally_available` as separate fields with evidence/status. Unknown availability is not treated as true. FireGuard v1 claims only **“no-look-ahead verified”** where Level A passes; it does not claim operational availability unless Level B passes.

The default strict models M1–M4 exclude GFS forecast channels. GFS/FiLM is a separate benchmark-assumption experiment. Historical GRIDMET/drought channels may be retained in the Level-A model only after confirming they do not include data from the target window; their publication latency is assessed separately under Level B.

### 2.4 Label source and confidence

- WSTS labels are based on the **Suomi-NPP VIIRS** active-fire product (the paper identifies VNP14IMG / S-NPP).
- The active-fire grid is 375 m; observation frequency varies by latitude/overpass.
- WSTS removes low-confidence detections; confirm the exact filtering in the dataset-generation code.
- The WSTS daily target is a binarized next-day active-fire map. Preserve the original target for the primary benchmark.
- Do not rebuild the target by mixing S-NPP with NOAA-20/NOAA-21 FIRMS observations.

### 2.5 Spatial grid, variable frame sizes and padding

- Use WSTS's native 375 m grid.
- WSTS frame dimensions vary (approximately 304×207 to 356×308 as reported); never assume a fixed 300×300 image.
- Pad each frame on the bottom/right to a multiple of **32** for the selected U-Net depth. Store the original H/W and a valid-pixel mask. Do not crop away edge regions for evaluation.
- Padded cells must be excluded from loss, AUPRC, F1, IoU, Brier and calibration metrics. Evaluate full original event frames after removing padding.
- Document CRS, affine transform, dimensions, nodata and resampling for all channels.
- Regridding coarse weather to 375 m does not create 375 m meteorological detail; treat it as regional context.

The plan is tiered. **WSTS is the training benchmark.** FIRMS is the current observation layer and a carefully matched comparison source. HLS is a conditional add-on. Other sources are validation or later features, not mandatory simultaneous inputs.

#### WSTS's 23 input channels — what they actually represent

WSTS combines source products and resamples them to the 375 m, 24-hour benchmark grid. The paper's feature overview describes these groups:

1. **Active fire:** S-NPP VIIRS active-fire mask / latest detection time within the day (375 m; 2–4 looks/day depending on latitude).
2. **VIIRS surface reflectance:** VNP09GA bands I1, I2 and M11, used as spectral proxies for vegetation/burn/cloud/smoke-related context (native resolutions roughly 500 m for I bands and 1,000 m for M bands).
3. **VIIRS vegetation indices:** VNP13A1 NDVI and EVI2 (500 m; 16-day compositing window with an 8-day product cadence, as described by the paper).
4. **Weather and fuel-moisture/fire-danger context:** GRIDMET daily minimum/maximum temperature, total precipitation, wind speed/direction, specific humidity, PDSI and Energy Release Component (ERC), among the listed variables.
5. **Weather forecast:** GFS forecast variables including wind, mean temperature, precipitation and specific humidity.
6. **Land cover:** MODIS MCD12Q1.061 IGBP land-cover class (~500 m, yearly).
7. **Topography:** SRTM elevation, slope and aspect (~90 m).

**Important correction:** WSTS has variables described as “fuel-related” (VIIRS reflectance/vegetation indices, land cover, weather/ ERC) but does **not** include a separate LANDFIRE-style fire-behaviour fuel-model raster or canopy structure product. Therefore M2 is “terrain + land cover,” not “terrain + fuel.” LANDFIRE is a separate optional enrichment.

**WSTS event and storage facts:** the paper reports 607 retained events and 13,607 daily images from 2018–2021. The events were queried as large fires (>1,000 ha) and the creation process adds four buffer days before and after the event. The 2019 fold has fewer events (74) than 2018 (176), 2020 (201) and 2021 (156). The Zenodo archive is 48.4 GB. The WSTS repository recommends HDF5 conversion for faster training and says HDF5 files take approximately twice as much space; plan storage accordingly.

**Licensing:** the WSTS GitHub README states the dataset is CC-BY-4.0 and the dataset creation/research code is MIT-licensed. Cite WSTS and preserve attribution. Still verify the exact Zenodo file metadata and any third-party source conditions before redistribution. Do not upload raw WSTS archives to the project repository.

#### HLS go/no-go protocol

The team's existing HLS Sample 02 analysis is useful as a **single-granule product EDA**, not a matched WSTS training input. Recorded sample findings:

- Fmask valid coverage: 99.96%.
- Water among valid Fmask pixels: 21.47%.
- Strict clear-land pixels: 8,136,107 (60.74% of the full tile).
- Relaxed clear-land pixels, allowing cloud-adjacent pixels: 8,666,016.
- Ten S30 bands and Fmask were explored; reflectance statistics, Fmask masks, NDVI/NDMI/NBR/NDRE, histograms, correlation and RGB composites were generated.

This one sample may be water-heavy and is not yet demonstrated to represent WSTS wildfire areas. Verify its geographic footprint and do not generalize its statistics to all HLS scenes. Run a high-aerosol sensitivity comparison: high aerosol can coincide with smoky/obscured scenes, so excluding it wholesale could remove precisely the difficult fire-adjacent observations the research may need. Store QA flags and compare (a) excluding high aerosol, (b) retaining with a quality channel, and (c) masking only the strongest invalid classes. HLS joins the model only if the explicit coverage/time/cost threshold above passes.

## 4. Data pipeline, input tensor, channel audit and leakage control

### 4.1 Input tensor specification

The pinned official WSTS loader is the source of truth for sample semantics, channel order, dimensions and target construction. Do not recreate its 23-channel data cube from a guessed channel list.

Conceptual input:

- `X_dynamic: [T, C_dynamic, H_pad, W_pad]`, with the exact sequence length/order taken from the WSTS sample/loader (five daily frames are the working candidate and must be unit-tested).
- `X_static: [C_static, H_pad, W_pad]`, including WSTS SRTM-derived topography and MODIS land-cover channels where present.
- **Default strict model:** no GFS channels. Retain only channels that pass Level-A no-look-ahead checks.
- **GFS benchmark-assumption branch:** separate optional input tensor, never silently merged into strict M1–M4.
- `Y_next_day: [1, H_pad, W_pad]`, benchmark-aligned next-day active-fire mask.
- `valid_pixel_mask: [1, H_pad, W_pad]`, true only for real in-frame/valid evaluation cells; false for padding and data-invalid cells as defined by the official loader.

All `H_pad` and `W_pad` values are padded to multiples of 32. Original `H`, `W` must be preserved in metadata for exact unpadding and evaluation.

### 4.2 Per-channel data dictionary and two-level leakage register

Create `docs/data_dictionary.md` and `docs/leakage_audit.csv`. Every channel must have, at minimum:

| Field | Meaning |
|---|---|
| `channel_name`, `source_product`, `product_version` | Exact data variable and product |
| `sensing_or_composite_window` | When the underlying observation/composite was formed |
| `forecast_creation_time`, `forecast_valid_time` | Forecast metadata, if applicable |
| `available_at` | Earliest verified time the source could be accessed |
| `no_lookahead` | `PASS / FAIL / UNKNOWN` for Level A |
| `operationally_available` | `PASS / FAIL / UNKNOWN` for Level B |
| `evidence` | Source metadata, code, documentation or timing test |
| `input_decision` | `STRICT / BENCHMARK_ASSUMPTION / EXCLUDE` |
| `native_resolution`, CRS, resampling, nodata, quality mask | Geospatial processing contract |

The two time-safety fields are independent. A channel may pass Level A and fail/unknown Level B. FireGuard must not describe a Level-A-only channel as operationally available.

### 4.3 Mandatory Phase-1 channel checks

1. **Daily windows and forecast origin:** inspect WSTS paper, data-generation code and actual sample metadata. Define exactly what each daily frame and the D+1 target represent.
2. **GFS issue/availability time:** inspect Earth Engine `creation_time`, `forecast_time`, initialization/run ID and valid-time range. Do not assume a 00Z run is published at 00Z. Record Level A and Level B separately. Default strict M1–M4 excludes GFS regardless; GFS/FiLM is a benchmark-assumption ablation only if Level A passes and provenance is documented.
3. **GFS wind-direction encoding:** inspect raw HDF5 min/max, percentiles and unique/sample values for the WSTS GFS wind-direction channel. A reported range near −90° to +90° may indicate an arctan-style encoding that has lost quadrant information. If confirmed, do not use it for downwind baselines or FiLM. Use GFS wind speed plus a verified GRIDMET direction only if its time semantics are suitable, or recompute direction from raw u/v if the original creation code/data provide both components. Otherwise disable wind-direction-dependent methods.
4. **GRIDMET and drought/ERC latency:** test whether each daily value includes only observations before target start (Level A), then separately verify publication/access latency (Level B). Lag or exclude any channel that crosses target start.
5. **VNP13A1 NDVI/EVI2:** inspect the 16-day composite begin/end timestamps and actual acquisition support. A composite nominally labelled before D may include observations after D or burn-scar information. If the composite window overlaps target start, lag/drop it from strict inputs. Document evidence; do not rely on the label date alone.
6. **VNP09GA daily reflectance:** verify acquisition/day window and data-availability semantics. It may be used as an **evaluation-only observability diagnostic** for the next-day window; it must never be fed to the model if it occurs after forecast origin.
7. **VIIRS active-fire mask and HHMM:** verify detections are restricted to the input daily window. Keep the binary active-fire mask as the primary fire-state input. Do not standardize HHMM as a normal continuous variable. If detection time is used, encode it as minute-of-day sine/cosine features only for valid fire pixels, with separate no-detection mask; test that it contains no target-day information.
8. **Static layers:** inspect product vintage and ensure a post-event product does not encode burn scars or later land-cover change.
9. **Angle variables:** inspect raw angular channel ranges. Encode circular quantities with sine and cosine only when the original angle covers the full circle. Never assume a sine-only or quadrant-limited representation can be repaired by adding cosine after information has been lost.
10. **Preprocessing:** fit normalizers, class sampling, feature selection, probability thresholds and calibration on train/validation only. Never use test events to choose them.

Each item must be labelled `VERIFIED`, `ASSUMED` or `LEAKY/EXCLUDED`, with links/screenshots/code evidence in the audit register.

### 4.4 Evaluation observability: “not detected” is not always “no fire”

The WSTS binary target does not provide a complete cloud-observability label for every next-day negative pixel. Some cells may be negative because the satellite did not observe/detect fire, not because no fire existed.

- Keep the original WSTS benchmark target and primary benchmark metrics unchanged for published comparability.
- Build a **supplementary observability-stratified evaluation** using next-day VNP09GA reflectance validity/QA, where available, to classify pixels/events into better-observed and poorly-observed strata.
- This next-day validity information is **evaluation-only**. It must never be a model input, a feature-selection input, or a pre-origin readiness signal.
- Report valid-observation coverage and metric differences between observability strata. Do not relabel unobserved cells as true negatives or claim the stratified evaluation is perfect ground truth.

### 4.5 Spatial processing, augmentation and padding

- Keep WSTS's native grid and documented resampling.
- Continuous rasters: use source-appropriate interpolation/area aggregation and document it. Categorical land cover and bit-packed QA: nearest-neighbour or class-mode; never bilinear-resample Fmask bits.
- Missing values use explicit masks/validity channels; do not silently replace with zero without a mask.
- Pad frames to a multiple of 32; mask padded cells in loss and every metric. Evaluate full frames after unpadding; do not center-crop test events.
- **Geometric augmentation is disabled by default** until transformations for directional variables are correct and unit-tested. Any flip/rotation must transform wind-vector components, wind direction and aspect consistently. Otherwise use non-geometric augmentations only (e.g. carefully chosen channel dropout/noise) and document them.
- For circular angle features, use sine/cosine only if full-circle source direction is intact. HHMM remains a categorical/time-of-day variable, not an ordinary continuous scalar.
- HLS (if it passes the go/no-go): apply scale 0.0001, mask fill values, decode Fmask, preserve observation age/valid fraction, and run aerosol-policy sensitivity. Do not always discard all high-aerosol pixels without reporting the coverage/smoke-related trade-off.

### 4.6 Class imbalance, crop policy and calibration

- Active-fire pixels are extremely rare (the WSTS paper reports around 0.1% at pixel level).
- Positive/fire-centred crops may be used for **training only** to improve optimization.
- Validation, calibration and test use full event frames at natural prevalence. Pad, do not crop, full-frame evaluation.
- Fit each fold's F1 threshold and calibrator using its event-level validation set only. Never calibrate on positive-biased crops or test data.
- If negative sampling is used, record the ratio and fit calibration on the un-sampled full-prevalence validation frames.
- Start with BCE + Dice; focal loss is an optional comparison. Apply valid-pixel masks to losses and metrics.

## 5. Deep-learning architecture

### 5.1 M1 — strict spatial baseline: 2D U-Net

- Input: WSTS fire-state mask and the selected VIIRS reflectance/vegetation channels that pass Level-A no-look-ahead audit. **No GFS channels** in the default strict model.
- Encoder: convolutional blocks and downsampling for local spatial features.
- Decoder: upsampling and skip connections for a per-cell output map.
- Head: one logit per cell; sigmoid gives `P(active-fire detection on D+1)`.
- Pad to a multiple of 32 and use an explicit valid-pixel mask.
- This is the required course CNN and the first deep-learning benchmark.

### 5.2 M2/M3 — static and temporal comparisons

- **M2: U-Net + static terrain/land cover.** Add WSTS SRTM-derived topography and MODIS land cover. This is “terrain + land cover,” not a separate fuel-model/canopy product.
- **M3: stacked-days U-Net.** Stack the audited daily input frames/channels in the channel dimension and learn temporal context with a spatial U-Net. This is the temporal non-recurrent comparator.

### 5.3 M4 — temporal model: U-Net + ConvLSTM

- Apply a shared CNN encoder to each audited daily frame.
- Feed spatial feature maps into ConvLSTM to learn temporal dependencies while preserving spatial structure.
- Decode the temporal representation into a next-day probability map.
- Compare against M3 on identical split manifests, loss masks, full-frame evaluation and comparable training budget.
- Retain ConvLSTM only if the fold-level paired results support the added complexity.

### 5.4 GFS/FiLM — benchmark-assumption ablation, not default

- Encode WSTS GFS forecast covariates with a small MLP/1D encoder and condition selected feature maps using FiLM.
- Keep this as a separate experiment after GFS Level-A no-look-ahead and wind-channel integrity checks. It is **not part of strict M1–M4**.
- If Level A passes but Level B fails/unknown, label it as a **benchmark-assumption historical experiment**, not operationally available.
- If GFS forecast direction has lost quadrant information, exclude that direction channel from FiLM and all downwind methods. Use only verified components/directions; if none exist, omit directional conditioning.
- ERA5/ERA5-Land are not substituted as future weather inputs; they are reanalysis/oracle context only and not part of the strict forecast model.

### 5.5 Experimental GNN (optional)

- Do not make every 375 m pixel a graph node; that graph is too large and may duplicate convolution.
- If compute/time permits, coarsen into patches (e.g. 5×5 WSTS cells, about 1.875 km per patch) and use a GCN or GAT.
- Node features: pooled CNN embeddings, fire state, terrain and land-cover features; use weather only when its provenance is suitable.
- Edges: 8-neighbour adjacency; wind alignment only if direction is verified; optional distance/slope attributes.
- Compare with a CNN at matched parameter count/compute. Keep only if event-level results justify it; otherwise report the negative result.

### 5.6 Optional HLS branch

HLS S30 is a feasibility study by default. Include it only if the Section 3.2 gate passes: at least 70% of candidate events have an acquisition within 14 days before origin with at least 50% clear-land coverage on the event AOI, and the retrieval/alignment pipeline costs no more than about one person-week.

If included:

- Use only imagery acquired before the forecast origin; record acquisition time, QA, age and clear fraction.
- Candidate features: selected reflectance bands plus NDVI, NDMI, NBR and NDRE.
- Aggregate 30 m data to the WSTS 375 m grid with geospatial area aggregation/reprojection. Do not reshape into fixed 12.5×12.5 blocks because 375/30 is not an integer.
- Add observation-age and valid-fraction channels; test stale/missing optical inputs and aerosol-policy sensitivity.
- The team's 2026 single-granule EDA is product familiarization, not evidence of historical WSTS-event coverage.

## 6. Baselines, experiment design and evaluation

### 6.1 Baselines

Binary baselines are valid for thresholded F1/IoU but provide only one ranking point and are degenerate for AUPRC. Include continuous-score baselines:

| Baseline | Output | Metrics / conditions |
|---|---|---|
| Persistence | Binary current-day active-fire mask | F1/IoU only; reference baseline |
| Dilated persistence | Binary dilation around current fire | F1/IoU |
| Distance-to-fire decay | Continuous score decreasing with distance from current active fire | AUPRC, Brier/BSS, F1/IoU |
| Downwind-weighted distance decay | Continuous score using distance and wind vector/direction | Only if a direction source passes encoding/time checks; otherwise omit |
| Distance-to-current-fire climatology | `P(next-day active fire | distance bin)` fitted on training events only | Soft AUPRC baseline and Brier Skill Score reference |
| Logistic regression / Gradient Boosting | Neighbourhood + audited features | Optional classical ML benchmark |

The distance-bin climatology is fitted inside each fold using training groups only. Never fit it on validation or test events. Do not use GFS wind direction in downwind baselines unless its quadrant integrity is verified. If no valid direction is available, report distance-only baselines.

### 6.2 Tiered experiment budget

The total experiment matrix must be capped after timing one run in Week 1. Avoid the full model × four folds × three seeds matrix for every optional feature.

| Tier | Experiments | Protocol |
|---|---|---|
| Tier 0 — smoke test | One sample, one seed | Loader, padding, loss, forward/backward, valid-mask metrics, timed run |
| Tier 1 — primary | Soft baselines, M1 U-Net, best among M3 stacked-days U-Net and M4 ConvLSTM | P1 four year folds; start with one seed, expand to three seeds only if runtime permits |
| Tier 2 — controlled modules | M2 terrain+land cover; GFS/FiLM benchmark-assumption branch; HLS if it passes; GNN if feasible | Two representative folds × one seed initially; expand only if a result is promising |
| Tier 3 — final reliability | Best supported model, calibration and optional small ensemble | Use fold-specific validation calibration; ensemble spread is indicative unless separately validated |

Early stopping: use **validation AUPRC on full, un-cropped event frames at natural prevalence**. Fix the epoch-selection rule before test evaluation. Store all configs, seeds and run hashes.

### 6.3 Two separate evaluation protocols and group-safe validation

**Related-fire grouping (used before any split):** construct an event graph. Connect two WSTS events if their event footprints overlap, or if their centroids are within **30 km** and the gap between their event-date intervals is no more than **14 days**. The connected-component procedure is a single-linkage rule, so chains of individually related events can create an unexpectedly large component. Before freezing groups, report the group-size distribution (number of groups by event count, median/upper percentiles, largest group) and, crucially, each group's share of the raw event count in every affected year. Use **20% of any year's events in one group** as a pre-registered warning threshold, not an automatic reason to split a genuinely connected complex. If any component exceeds it, inspect the event map and dates; then either tighten the distance/time thresholds or construct a complete-linkage alternative so every pair in a group satisfies the chosen relation. Record the chosen rule and all group counts. Retain the wider **50 km / 30 day** sensitivity check and compare group-size/fold-size distributions under both rules. Never split one frozen group across train/validation/test. If a group spans calendar years, assign the entire group to the year of its earliest event start date for P1; report raw event-year counts and post-grouping group/event counts per fold.

Run two protocols separately; do not combine their folds or imply they are one crossed validation design:

- **P1 — leave-one-year-out (LOYO):** for test year Y, all `fire_complex_group_id` groups assigned to anchor year Y are the test set. Groups spanning calendar years stay entirely in the anchor-year fold; they are never split across folds. From the remaining three anchor years, hold out approximately 15–20% of groups as validation; the remaining groups are training. Keep validation groups whole. Repeat for 2018, 2019, 2020 and 2021. Report raw event-year counts and actual post-grouping event/group counts separately; 2019 has fewer raw events and may have lower power/wider intervals.
- **P2 — western-US geographic holdout:** select one ecoregion within the WSTS western-US domain and hold out every entire group that intersects it across all years. If a group crosses the ecoregion boundary, keep the complete group in the test set rather than allowing related events into training. From the remaining-region groups, create a separate group-level validation subset; train on the rest. This protocol is run independently and is not combined with P1.

For each fold/protocol:

1. Freeze train/validation/test group manifests before fitting.
2. Fit normalization and feature selection using training only.
3. Use validation full frames for early stopping, F1 threshold selection and probability calibration.
4. Fit a separate calibrator for each held-out fold/protocol. Do not pool differently calibrated folds into one reliability curve.
5. Evaluate once on the held-out test groups. Store OOF predictions only for the events/groups held out in that fold.
6. Hash split manifests and record the event/group IDs in the run config.

### 6.4 Evaluation observability and label limitations

The primary benchmark metrics use the original WSTS target over the benchmark's valid image footprint. Because the binary target cannot distinguish “not burning” from “not observed/detected,” add a supplementary observability analysis:

- Derive next-day VNP09GA reflectance-validity/QA coverage for the relevant cells/events where available.
- Use it only after prediction to stratify evaluation into better-observed and poorly-observed cells/events and report coverage with each stratum.
- Never pass next-day VNP09GA or its validity mask into the model or input-readiness panel.
- Keep primary benchmark scores unchanged and clearly label observability-stratified metrics as a diagnostic, not perfect fire ground truth.

### 6.5 Metrics

| Objective | Metric | Reporting rule |
|---|---|---|
| Primary discrimination | **AUPRC / Average Precision** | Continuous scores; pooled pixels and per-event macro-average |
| Thresholded spatial skill | Positive-class F1 and IoU | Threshold chosen on each fold's validation set only |
| Probability skill | Brier Score and Brier Skill Score | BSS reference is training-fold distance-bin climatology; evaluate at natural prevalence |
| Calibration | Equal-mass-bin ECE, reliability slope, reliability diagrams | Separate reliability/calibrator per fold; avoid pooling incompatible calibrators |
| Generalization | P1 unseen year; P2 unseen western ecoregion | Report degradation explicitly |
| Observability | Metrics stratified by next-day VNP09GA validity | Evaluation-only diagnostic; report coverage |
| Robustness | Missing/stale HLS and aerosol-policy sensitivity, if HLS used | Report retained coverage and metric changes |
| Explainability | Deletion/insertion, randomization sanity check, explanation stability | Associational evidence, not causality |

Report both pooled pixel-level scores (benchmark comparability) and per-event macro-average scores (to prevent a few mega-fires dominating). For model comparisons, run a **paired bootstrap over events/groups**, not over pixels. Report confidence intervals and the low-power 2019 fold caveat.

### 6.6 Development targets and gates

- Development target: aim for at least 10% relative AUPRC improvement over the strongest soft baseline, but this is an aspiration, not a promised result.
- Primary statistical evidence: pooled paired event-level bootstrap 95% CI for the per-event AUPRC difference excludes zero.
- Report each year fold separately. “Improves in 3 of 4 years” is supporting evidence, not the primary success rule.
- Keep an added module only if its paired event-level AUPRC difference has a confidence interval above zero on at least two evaluated folds, or explicitly report the negative result and drop it from the final model.
- If M1 does not match/beat the best soft baseline at Gate 2, stop architecture expansion and diagnose target, no-look-ahead inputs, sampling, padding and class imbalance first.

### 6.7 Research hypotheses and novelty framing

Do not claim that FireGuard invents U-Net, ConvLSTM, GNN or wildfire forecasting. The WSTS paper already compares U-Net, ConvLSTM, UTAE and classical baselines. Frame the contribution around the evaluation protocol and evidence. Pre-register at least these hypotheses:

- **H1 — static context:** adding WSTS SRTM topography and MODIS land cover to fire-state inputs improves event-macro AUPRC over the fire-state-only U-Net.
- **H2 — temporal modelling:** ConvLSTM improves next-day forecast AUPRC over a stacked-days U-Net on identical grouped folds and full-frame evaluation.
- **H3 — probability quality:** fold-specific calibration improves Brier score/reliability compared with the uncalibrated model, even if AUPRC is unchanged.
- **H4 — optional data/architecture:** HLS and/or GNN adds value only if its gated ablation improves results; a null/negative result is a valid finding.
- **H5 — GFS/FiLM benchmark-assumption branch:** adding the audited GFS forecast channels through FiLM improves AUPRC over the strict no-GFS model under the WSTS benchmark assumption. This is a research ablation only; it does not imply Level-B operational availability. A null or negative result is a valid finding.

### 6.8 Reproducibility and experiment registry

- Fix Python/NumPy/PyTorch seeds; enable deterministic algorithms where supported and record any nondeterministic operations.
- Pin the WSTS loader repository commit and record the exact commit hash in every run.
- Hash the full experiment config (data channels, splits, model, loss, sampling, optimizer, augmentation, seed, checkpoint selection).
- Record early-stopping metric: validation AUPRC on full frames at natural prevalence.
- Store train/validation/test IDs, metrics, checkpoint path, package versions, GPU model/runtime and config hash.
- Save the explanation-consistency result across ensemble members/seeds and attribution methods if explanations are implemented.

## 16. Final recommended v1 lock — v4

WSTS includes VIIRS fire/reflectance/vegetation channels, GRIDMET weather/drought, GFS forecast channels, MODIS land cover and SRTM-derived topography; verify exact channels in the pinned loader. Padding to 32 and valid masks are mandatory. No geometric augmentation until directional variables are transformed correctly.

**Evaluation:** binary and soft baselines; AUPRC primary; pooled and event-macro metrics; paired bootstrap over fire-complex groups/events; nested event-group validation inside each LOYO fold; separate western-US ecoregion holdout where schedule permits; fold-specific thresholds/calibrators; full-frame natural-prevalence evaluation; next-day VNP09GA observability only as an evaluation diagnostic; group-size diagnostics before freezing splits; precomputed OOF predictions for replay.

**Application:** global FIRMS observation-only Live Monitor plus a historical Forecast & Replay Lab that retrieves precomputed OOF artifacts. No live FireGuard forecast, no model inference in backend, no learned smoke prediction, no emergency alerts and no global forecast-validation claim in v1.

**Engineering:** create repository/CI in Week 1; FastAPI + PostgreSQL; React + MapLibre; static PNG/GeoTIFF/JSON artifacts; FIRMS server-side proxy/cache with ≤5-day chunks pending live API-contract verification; 150–200 GB storage planning estimate; GPU/fallback confirmed in Phase 1; explicit Gate 1 minimum and cut order; one buffer week reserved after Week 10.

This scope retains real multimodal deep-learning research and a demonstrable application while making the data-time assumptions, evaluation design and runtime boundaries explicit.
